# 09-构建与运行说明

本章覆盖工具链、工作区结构、测试组织、cassette 录放、xtask 验证与发布规则。

---

## 🧰 环境准备

- **Rust 工具链**：仓库 `rust-toolchain.toml` 固定 **1.97.1**（含 rust-analyzer / rust-src 组件与 `wasm32-unknown-unknown` target）。
- **nextest**：0.9.91+（读 `.config/nextest.toml` 的测试优先级；更旧版本能跑但按默认顺序）。
- **Clippy / rustfmt / protoc**；**Docker**（存储套件）；**Node**、**wasm-bindgen-test-runner**（锁文件版本）、**Python 3.12+**（依赖 floor 检查）。
- workspace lints（根 Cargo.toml）：`clippy::dbg_macro` forbid；`await_holding_lock`、`await_holding_refcell_ref`、`expect_used`、`expect_fun_call`、`indexing_slicing`、`panic`、`panic_in_result_fn`、`unreachable`、`unwrap_used` deny，`todo!`/`unimplemented!` forbid——写库代码不能用裸 unwrap/expect/panic。

```bash
git clone https://github.com/0xPlaygrounds/rig.git && cd rig
rustc --version    # 1.97.1，由 rust-toolchain.toml 固定
```

## 🧱 工作区结构

| 路径 | 说明 |
|------|------|
| `crates/*` | 31 个子 crate（core/agent/ecs/http/reqwest/tungstenite/harness/harness-protocol/tools/cassette/…/各向量库与推理） |
| `plugins/*` | 4 个 rig-harness 插件 crate（rig-basics / rig-inspect / rig-steel / rig-tui），构建进最终 harness 二进制 |
| `corpus/*` | 17 个 `publish=false` 的塑形测试插件包，CI 全量构建 |
| `examples/*` | 68 个示例，**每个是独立 workspace 包**（根 manifest `autoexamples = false`） |
| `tests/` | 根集成测试目标：`tests/<provider>.rs`、`tests/providers/<p>/{cassette,live}/`、`tests/core.rs`、`tests/ecs_parity/`、`tests/integrations/` |
| `crates/rig-cassette/fixtures/cassettes/<provider>/` | 1100+ 回放 fixture（cassette 引擎随 crate 内 fixtures 走；发布包 `exclude = ["fixtures/**","tests/**","benches/**"]`，运行时读） |
| `test-support/service-tests`、`test-support/rig-test-support`、`test-support/rig-harness-test-support`、`test-support/rig-defaults-test-support`、`test-support/rig-history-conformance` | 未发布的服务测试 runner、共享断言 / ECS golden 基线 / harness 插件测试支撑 / 历史一致性 |
| `xtask/` | `cargo xtask verify` 验证规划器 |
| `src/main.rs` + `src/launcher/` | 根 crate 同时是 `rig` 命令的 launcher（生成插件化 harness 工程并构建） |

`default-members`（根 Cargo.toml）列出裸 `cargo nextest run` 必跑的包（#2258 的教训：不列的话约 1200 个 rig-core 单测不会在任何 CI 步骤执行）：`.`（facade）、`rig-core`、`rig-cassette`、`rig-agent`、`rig-http`、`rig-reqwest`、`rig-tungstenite`、`rig-typesafeai`、`rig-bedrock`、`rig-candle`、`rig-gemini-grpc`、`test-support/service-tests`、`test-support/rig-test-support`、`test-support/rig-history-conformance`、`examples/frozen_api`。`rig-derive` 刻意不在默认集（proc-macro 测试动态链接 libstd，破坏未装 dylib 组件的工具链），由点名 `-p rig-derive` 的专属 CI job 覆盖；`examples/discord_bot` 自成 workspace 被排除（rustls 顾问未修）。

## 🧱 构建与检查

```bash
cargo build                                   # 默认成员
cargo build -p rig-core --all-features        # 单包全特性
cargo clippy --all-targets --all-features      # 按仓库 lint 规则
cargo fmt
cargo doc --workspace --no-deps --all-features
cargo build --target wasm32-unknown-unknown    # WASM 目标必须可编译
```

WASM 贯穿性约束：公共 trait 用 `WasmCompatSend/Sync`；错误装箱遵循平台分支 bound；`--cfg rig_loom` 是模型检查的构建标志（选 rig-agent `sync.rs` 的 shim），不是 feature。

## 🧪 测试组织与规则

**测试模块是兄弟文件，禁止内联**：`#[cfg(test)] mod tests;` + `foo/tests.rs`（`foo.rs` 旁）或 `mod.rs` 旁的 `tests.rs`。CI 用 `cargo xtask check-test-layout` 强制。

层级：

1. **单元测试**：紧邻实现的兄弟 `tests.rs`（如 `client/tests.rs`、`agent/hook/tests.rs`、`error/tests.rs`）。
2. **cassette 回放（provider 回归默认证据）**：代码在 `tests/providers/<provider>/cassette/`，fixture 在 `crates/rig-cassette/fixtures/cassettes/<provider>/`（随 cassette 引擎走），回放**不需要 API key**。引擎是 workspace crate `rig-cassette`，facade 通过 feature `cassette` 暴露 `rig::cassette`。
3. **live 测试**：`tests/providers/<provider>/live/`，`#[ignore]`，需真实服务与 key。
4. **ECS 对齐矩阵**：`tests/providers/<p>/cassette/ecs_*.rs`（faults/matrix/checkpoint/image/stream_delivery/…）+ `tests/ecs_parity/`；身份基线钉在 `test-support/rig-test-support/src/ecs_goldens/identities.json`。
5. **服务型向量库**：`test-support/service-tests`（Docker，CI 慢车道）。
6. **corpus 套件**：`corpus/*` 是 17 个 `publish=false` 的真实插件包，针对 rig-harness 公开 API 写成；CI 全量构建并跑它们的测试，作为 kernel 改动的回归网。

回放命令（`--test-threads=1`）：

```bash
cargo test -p rig --all-features --test openai openai::cassette -- --nocapture --test-threads=1
cargo test -p rig --all-features --test anthropic anthropic::cassette -- --nocapture --test-threads=1
cargo test -p rig --all-features --test gemini gemini::cassette -- --nocapture --test-threads=1
```

录制（需该 provider 的真实 key，**覆盖 fixture**，完成后必须复查 diff）：

```bash
RIG_PROVIDER_TEST_MODE=record \
  cargo test -p rig --all-features --test openai openai::cassette -- --nocapture --test-threads=1
```

fixture 安全纪律：不得含 API key / bearer token / cookie / provider 账号标识 / 无关 churn；`tests/common/cassette_safety.rs` 有洗刷检查，但录制者仍须亲自审 diff。

测试学说（`tests/README.md`）：**录制的 provider 流量是默认证据，provider 的真实 API 才是代码对错的最终裁判**——#2258 重构期发现的每一个流式 bug 都来自 live 录制而非合成语料。

## 🔎 验证哲学（DEVELOPING.md）

**本地跑最小相关检查，发布靠 GitHub CI 全面覆盖**：

```bash
cargo xtask verify --changed --dry-run       # 预览选择（共享输入会选中全量计划）
cargo xtask verify --changed                  # 可选；仅当选区足够小时
cargo xtask verify --pr --base <base>         # PR 门禁同款（可选）
cargo xtask verify --full                      # 全量含慢车道（可选）
cargo xtask verify --check <id>               # 显式单检查
```

- 默认**不要**本地跑全 workspace / 全 feature / 全 provider / docs+doctest / WASM / Docker / 依赖 floor 矩阵——那些属于 CI；确需昂贵检查先说明具体理由。
- 文档/说明类改动只审 diff 与链接一致性，不跑 Rust 套件。
- 验证永远 `RIG_PROVIDER_TEST_MODE=replay`，从不录制、从不再生成 golden。
- CI 的慢车道（`full-tests`：全特性 + Docker 存储套件 + feature 转发守卫；`dependency-floors`：最低声明版本全 workspace 构建）跑在 merge queue / nightly / release gate；`slow.yaml` 与本地 planner 是同一套选择逻辑，两边不会不一致。

## 📦 发布与变更文档

- **`CHANGELOG.md`、`crates/*/CHANGELOG.md`、`MIGRATING.md` 是生成物，禁止手改**（CI 拒收 PR）。变更条目与迁移说明写进 PR 描述的 `## Changelog` / `## Migration` 小节；发布 PR 由 `scripts/release-notes.sh` 再生成这些文件。当前 main 处于 **v0.44.0 之后**的 "0.41 → 0.45" 迁移窗口。
- 发布流程：release-plz（`release-plz.toml`）；workspace 版本统一继承 `0.44.0`。
- `publish = false` 的成员：`corpus/*`（17 个塑形插件包）、`test-support/*`（rig-test-support / rig-harness-test-support / rig-defaults-test-support / rig-history-conformance / service-tests）。**rig-ecs / rig-harness / rig-tools / rig-cassette 均已发布**（注意 rig-ecs 在 0.43–0.44 期间被替换过一次，新 crate 版本从 >0.44 起算）。
- 依赖 floor 规则（根 Cargo.toml workspace.dependencies 注释）：**floor 是下限不是 pin**——"有新版本就抬 floor"是违规；Dependabot 配置成只动 lockfile。
- 发布的 `rig-cassette` tarball `exclude = ["benches/**", "fixtures/**", "tests/**"]`（839 个 provider cassette 66 MiB + 206 个 effect golden + chat parity 快照约 1 MiB，否则会突破 crates.io 10 MiB 上限；fixture 是运行时读的，不影响编译）。

## 🧩 总结

- 工具链由仓库钉死（1.97.1 + nextest + Docker），clone 即可复现。
- 测试布局有 CI 守卫（兄弟文件、default-members），cassette 回放是 provider 回归的默认证据，录制纪律防泄密。
- 本地验证最小化、CI 全面化：`cargo xtask verify` 是可选规划器，不是发布闸门。
- 变更文档走 PR 描述，CHANGELOG/MIGRATING 由发布流程生成——动它们会被 CI 拒收。
