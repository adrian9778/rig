# 09 · 重构实现清单：从零重写一个功能等价的 Rig

> 本篇把前 8 篇的阅读变成施工计划：按阶段列出**要建的 crate/模块/trait、依赖顺序、每阶段的验收标准（可执行的测试形态）**。目标不是像素级复制，而是重放同样的架构不变量：provider 无关、传输注入、sans-IO run、效果过线可序列化、错误可分类。

## 阶段 0：工程骨架

**建什么**

- workspace：facade crate（纯 re-export）、`core`、`derive`（proc-macro）、`agent`、两个传输 crate、test-support；examples 为独立成员包。
- 固定工具链与 edition；lints：禁 `dbg/todo/unimplemented`，deny `unwrap_used/expect_used/panic/await_holding_lock`。
- WASM 三件套：`WasmCompatSend/WasmCompatSync/WasmBoxedFuture` + 平台化 boxed 错误 bound。

**验收**

- `cargo build --target wasm32-unknown-unknown -p core` 通过。
- `cargo fmt --check`、`cargo clippy --workspace -- -D warnings` 通过；测试只能写兄弟文件（test-layout 检查）。

## 阶段 1：传输契约与一个具体传输

**建什么**（对应 02-03）

- `http_client`：重导出 `http` 类型；`HttpClientExt { send / send_multipart / send_streaming }`、`LazyBody`、`MultipartForm/Part`、`Error`（transport/instance/status 三分类要早定，重试表依赖它）、`BoxedHttpClient` 擦除。
- SSE：`GenericEventSource<H, Req, Retry=ExponentialBackoff>` + `RetryPolicy`；multipart。
- reqwest 传输 crate：impl `HttpClientExt`，给 `new(key)/from_env()` 便利构造。

**验收**

- mock 传输上单测：普通字节、multipart、流式、非 200 带体、SSE 断线重连次数与退避。
- 同一个 provider 模型在 mock 与 reqwest 传输上行为一致（后者可用录制 fixture）。

## 阶段 2：canonical 消息模型与补全契约

**建什么**（对应 02-01）

- `Message`（system/user/assistant/tool）、`UserContent/AssistantContent/ToolResult`、`Document`、`Usage`、`CompletionRequest/Response`。
- `CompletionModel { completion, stream, completion_with_context }`、`CompletionError`（含保留原始响应的 `ProviderResponse`）与 `ProviderResponseError`（status/body/headers/request-id）。
- 请求 builder：`completion_request(prompt)..build()`。
- `streaming`：`StreamEvent/Delta/BlockClose/ToolCallEnd`、`BlockId` 合成、`BlockAccumulator`（折叠必须等价非流式）、`PauseControl`。
- 线错误：`ErrorReport/ErrorKind`、`retryable_status`（408/425/429/5xx）、`transient_transport`、各域错误的 `From`。

**验收**

- 属性/快照测试：任意 delta 流折叠结果 = 同内容的非流式响应；缺 id 的工具调用得到稳定合成 id。
- 错误表单测：状态码×transport 错误的 retryable 矩阵；429 能读 Retry-After。

## 阶段 3：第一个 provider 与 internal 引擎

**建什么**（对应 03）

- `Provider` trait + `ApiKey/BearerAuth/Nothing` + `Client<P,H>` + 类型状态 `ClientBuilder<P, Missing→H>` + `ProviderClientError`。
- 能力 trait：先做 `HasCompletion/CompletionClient` blanket。
- internal：sans-IO `WireAdapter`（帧→事件纯函数）、严格帧分类（禁 untagged 兜底）、`tool_call_bridge`（index→id）、`chunk_lifecycle`、2xx 错误信封、schema 清洗。
- provider A（OpenAI Chat 形）：泛型 `GenericCompletionModel<Ext,H>` + profile trait；provider B 用它做"薄包装"（unit struct + Provider + Has* + 一个 profile 钩子），验证复用成立。
- cassette 设施：录制/回放传输 + 测试组织 `tests/providers/<p>/cassette/` + fixture 安全扫描。

**验收**

- 薄包装 provider < ~150 行胶水即通过与 provider A 相同的流式 conformance 套件。
- 录制→回放确定性：同一测试无网络、无 key 通过；fixture 扫描零密钥。
- 未知 SSE 帧在测试里"藏不住"（unknown 值断言）。

## 阶段 4：工具、嵌入、向量、其余能力

**建什么**

- 工具：`Tool`（&mut ToolContext）、`PortableTool` + blanket、`ToolContext`（键槽 + scopes 不上线）、`ToolExecutionError/ToolErrorKind` 单表、`ErasedTool` 唯一执行路径 → `ToolResult` 四结局；`#[tool]` 派生 Args/schema/impl；`DynamicTool`。
- 嵌入：`EmbeddingModel`（实现者只写完整响应方法，保序）、`Embed` derive、`EmbeddingsBuilder`。
- 向量：`InsertDocuments`、`VectorStoreIndex { type Filter; top_n; top_n_ids }`、`VectorSearchRequest`（查询是文本）、内存实现 + LSH；索引自动成工具的 blanket。
- rerank/transcription/image/audio/model-listing/verify：同一五步法（canonical 类型→trait→Has*→过线适配→provider 接线）；internal 各放一个 Generic 模型。

**验收**

- 一个类型化工具、一个 `#[tool]` 函数工具、一个 DynamicTool、一个向量索引工具，四条注册路径在同一执行路径上产出同形 ToolResult。
- 嵌入保序测试（乱序即失败）；`top_n_ids` 与 `top_n` 同序。
- 能力缺失在**编译期**体现（没有方法），无运行期能力表。

## 阶段 5：sans-IO agent run

**建什么**（对应 04-01/04-04）

- `RunSpec` → `AgentRun`（全 Serialize）：`AgentRunStep::{CallModel, CallTools, Done}`、`PendingToolCall{tool_call, preresolved_result, block_id}`、输出模式状态、usage、completion_calls。
- driver 喂回口：`model_response/tool_results`；流式 turn 的提交/回滚。
- `PromptResponse`（output/usage/completion_calls/messages/memory_append/raw）；`OutputMode` 四模式（合成输出工具、native、prompted、auto）。
- `AgentConfig`/`AgentBuilder`（类型状态：`.tool()` 切态、`build() -> Agent` 无 Result）、`Agent.prompt()/prompt_typed()`。
- 提取器：`Extractor<T>` = Tool 模式 + submit 合成工具 + Required + 单轮 + 重试预算（证明无需第二引擎）。

**验收**

- 手写 driver 单步驱动示例（对照 `agent_run_stepping`）：序列化到另一进程后 resume，工具调用 id 连续、不重新 mint。
- run/stream 两表面由同一驱动核产出；turn 重试回滚已 yield 内容的记账正确。
- 提取：无 submit→预算内重跑且 usage 累计；补全调用自身失败不计 usage。

## 阶段 6：effect bus 与 hooks

**建什么**（对应 04-02、07）

- `EffectKind` 七族 serde 词汇 + `FamilyDescriptor`；`Serve` handler 契约与各适配器；`HandlerKey`。
- bus 三角色：Dispatcher/Registrar/BusDriver；`BusClosed/HandlerUnavailable/Denied` 语义；Layer deny → 模型可见的跳过结果。
- `AgentHook`：13 事件、每事件独立动作枚举；HookStack 的 merge 语义（patch 累积、deny 首胜、replace 链、select 后者赢）；`RequestPatch` 合并规则与非黏性；`observes` 硬门；`RunSettled` 恰一次。
- 非法工具调用恢复五动作 + 预算；工具并发。
- record/replay：effect log 头（程序身份：hook 名、模型、策略版本），分歧 = `Divergence` 失败。

**验收**

- run 与 stream 上每个 hook 事件行为一致的对照测试。
- 记录一次 run 后离线 replay 全绿；改写一个效果即 Divergence；driver 关闭后派发即 BusClosed 且不重试。
- 内存族/检索族 dispatch 默认观察不到，opt-in 后可以拒绝。

## 阶段 7：记忆与伴侣生态

**建什么**

- `ConversationMemory`（boxed future、object-safe）+ 内存实现；`MessageFilter/DemotionHook/Compactor` 钩子。
- 策略 crate：滑动窗口/token 窗口/降级/摘要四适配器（套任意存储）。
- 一个服务式向量 crate（薄：查询翻译）与一个嵌入式 crate（厚：表/事务）；facade feature=模块名；service-tests 用容器。
- 本地模型 crate：ONNX 嵌入与 CPU 补全各一（实现对应 trait，证明非 HTTP 传输也成立）。

**验收**

- 同一策略套在内存/自建存储上行为一致；窗口挤出消息经 demotion hook 进向量长尾后可被检索回 prompt。
- 伴侣 crate 用 path+version 双依赖、`default-features=false`；服务测试无容器时 skip 而非红。

## 阶段 8：ECS 运行时（可选/实验）

**建什么**

- 效果=实体生命周期（Pending→InFlight→Outcome，Streamed 累积）；handler=实体 + 绑定表；因果=父子；取消=despawn；Gate/Judge 拦截实体。
- 系统集与"每 tick 到静默"驱动（静默上限）；**唯一**请求构造点；场景存取；replay 身份（scope/策略版本/policy hash）。
- parity 矩阵 + golden identities。

**验收**

- 同一 cassette 在 agent 与 ecs 两运行时上的效果序列/身份一致（parity 测试）；取消一个在飞补全 = 实体消失且无结果回灌。

## 横切验收（每阶段都适用）

1. 所有新 fallible API 用 thiserror 枚举，不用 String；无 `unwrap/expect/panic` 进库代码。
2. 每个 trait 方法 Send/Sync 走 WASM 兼容别名。
3. provider 改动配最小回归（内联测试优先，cassette 次之，live 最后）。
4. 文档示例与真实常量/路径/feature 一致；生成物（CHANGELOG/MIGRATING）不手改。
5. 不发明 provider 不存在的字段；新增错误分类同时更新转换与重试规则。

## 最小可演示里程碑（如果只做 MVP）

阶段 0→1→2→3（一个 Chat 形 provider）→5（先直接调用模型，不过 bus）→ 工具最小集。得到：可发补全、可流式、可多轮工具调用、错误可重试、可换传输的一个能用内核；bus/hook/ECS/记忆/向量是其后的增量，不回头破坏已有契约。
