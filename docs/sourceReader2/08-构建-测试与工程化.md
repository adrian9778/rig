## 2. Lints（`Cargo.toml:81-99`）

- `rust.unexpected_cfgs = warn`，白名单只留 `cfg(rig_loom)`（模型检查器的同步垫片开关；是构建标志不是 feature，crate 级，避免 event-listener 对裸 `loom` 起反应）。
- clippy：`dbg_macro/todo/unimplemented = forbid`；`await_holding_lock/await_holding_refcell_ref/expect_used/expect_fun_call/indexing_slicing/panic/panic_in_result_fn/unreachable/unwrap_used = deny`。
- 含义：库代码不能 `.unwrap()/.expect()/panic!`（用 `?` 与显式错误）；持锁跨 await 直接被拒。测试里需要 panic 断言时走测试专用豁免写法。

## 4. 构建与 WASM

```bash
cargo build -p rig-core                       # 核心
cargo build -p rig --all-features             # 全特性（CI lane）
cargo build --target wasm32-unknown-unknown -p rig-core   # 目标已在工具链预装
```

WASM 纪律：bound 用 `WasmCompatSend/WasmCompatSync`、future 用 `WasmBoxedFuture`；boxed 错误按 `#[cfg(target_family = "wasm")]` 去掉 `Send + Sync`；tungstenite 仅 native。

## 5. 五层测试

1. **单元/契约测试**（兄弟文件，`src/foo/tests.rs` + `#[cfg(test)] mod tests;`）：mock 模型/传输（`test_utils/`）。`cargo xtask check-test-layout`（xtask/src/test_layout.rs）强制布局，内联 `mod tests{}` 不合规。
2. **provider 内联测试**：各 provider 模块的 `tests.rs`（OpenAI responses_api 单文件测试就 2800+ 行）。
3. **cassette 回归**（仓库根 `tests/providers/<p>/cassette/` + 流量 `tests/cassettes/<p>/`）：默认回放，无需 key。
4. **ECS parity**：`tests/ecs_parity/`，多 provider 线（OpenAI Chat/Responses、Anthropic、Gemini、DeepSeek、Doubleword、Venice、OpenRouter、xAI）在两个运行时对齐，golden `identities.json`。
5. **外部服务集成**：`test-support/service-tests`（testcontainers + httpmock，Docker，慢车道）与 provider `live/`（真实 key，`#[ignore]`）。

回放命令：

```bash
cargo test -p rig --all-features --test openai openai::cassette -- --nocapture --test-threads=1
cargo test -p rig --all-features --test anthropic anthropic::cassette -- --nocapture --test-threads=1
cargo test -p rig --all-features --test gemini gemini::cassette -- --nocapture --test-threads=1
```

录制（覆盖 fixture，需要 key）：

```bash
RIG_PROVIDER_TEST_MODE=record \
  cargo test -p rig --all-features --test openai openai::cassette -- --nocapture --test-threads=1
```

fixture 安全：录制后必审 diff——不得含 API key、bearer、cookie、账号标识；`tests/common/cassette_safety.rs` 有自动扫描但不免除人工责任。录制要"最小命中"，只录被改的 provider/用例。学说见 `tests/README.md`：fixture 是测试运行时从 `CARGO_MANIFEST_DIR` 读取的回放数据，从不 `include_*!` 进编译产物。

## 6. xtask（`xtask/src/main.rs:27`）

```bash
cargo xtask check-test-layout
cargo xtask verify --changed            # 按改动选择检查
cargo xtask verify --pr --base <REF>    # PR 视角（必须显式 --base，不隐式 main）
cargo xtask verify --lanes --base <REF>
cargo xtask verify --full               # 全量（CI 矩阵，本地通常不跑）
cargo xtask verify --check <ID>         # 单跑一个检查
```

参数互斥（verify.rs:52-83）：五个模式恰好选一。check 定义在 `verify/checks.rs`（如 `fmt` → `cargo fmt --all -- --check`），另有 preflight/selection/execute/tests 模块。replay-only 是默认：本地不做录制、不起 Docker。

## 7. 最小本地验证哲学（AGENTS.md / DEVELOPING.md）

- 文档/注释改动：只审 diff 与链接一致性，**不编译、不跑测试**。
- 代码改动：跑最小相关检查；不要自动跑 workspace/all-features、全 provider/example、doctest、WASM、Docker、依赖下限矩阵，也不要本地装 CI 专用重依赖（先说明必要性）。
- 全面验证交给 GitHub CI；PR 打开后检查 required CI 是否覆盖验收标准，缺覆盖要显式报告。
- 失败做针对性修复，禁止禁用作业/跳过红检查/`--no-verify`。

## 8. 发布纪律

- **生成物禁止手改**（CI 拒收）：`CHANGELOG.md`、`crates/*/CHANGELOG.md`、`MIGRATING.md`、`docs/migrations/`。变更条目写进 PR 描述的 `## Changelog` / `## Migration`；release PR 由 `scripts/release-notes.sh` 与 `scripts/release-notes-prompt.md` 的编辑 pass 重新生成。
- release-plz 驱动发布；只有显式的 release PR 分支才碰生成物。
- 发布包体积注意：大 fixture 用 `exclude`，不要塞进 crate 目录。

## 9. 常见坑速查

| 现象 | 原因/处理 |
|---|---|
| 裸 `cargo test` 好像没测 rig-core | 历史上 default-members 缺失；现在已显式列出，仍建议用 `-p rig-core` 明确 |
| 新加内联 `mod tests {}` CI 红 | 布局规则：改兄弟文件 `tests.rs` |
| cassette 回放要网络/key | 默认就是 replay；检查是否误用 live 模块或没开 `--test <name>` |
| WASM 编译报 Send | 用 WasmCompat* 与平台分支错误 bound |
| PR 改了 CHANGELOG 被拒 | 生成物——移到 PR 描述 |
| `cargo xtask verify --pr` 报错要 base | 必须 `--base origin/<基线>`，无隐式 main |
